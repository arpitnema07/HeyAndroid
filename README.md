# HeyAndroid

An Android assistant that remembers things for you. Ask it by voice, text or a
screenshot, and it files what matters into a local memory store that it can
search later - then answers questions, sets reminders and drives the device
using that memory.

Kotlin, Jetpack Compose, Hilt, Room and WorkManager. Everything personal lives
on the device; no account, no backend of its own.

## What it does

- **Ask, dictate or capture.** A bar on the home screen takes typed text, voice
  (via the system speech recogniser) or a screenshot, and routes each one to the
  right place: a question goes to the assistant, a statement goes into memory.
- **Memory.** Notes, reminders, tasks, items, money entries and progress are
  stored in Room and indexed with a local embedding model, so recall works
  offline. A `MemoryEngine` decides what is worth recording and when a reminder
  is due.
- **Assistant.** A tool-calling chat loop that can search memory, write notes,
  read and update the reminder list, launch device intents, search the web, call
  MCP servers and call your own custom HTTP tools. Reminders go through
  `AlarmManager` and the calendar rather than a polling worker.
- **Providers.** Any OpenAI-compatible endpoint (OpenAI, Gemini's compatibility
  API, OpenRouter, local servers). A settings picker keeps a model list fresh
  from the endpoint, a scoreboard tracks which models actually answer, and a
  fallback ladder retries down the list when one fails.
- **SyncPad.** Clips pushed to a SyncPad server are browsable in-app and on two
  home screen widgets, with copy-from-widget, paste-clipboard-into-SyncPad and
  tag filtering.
- **Widgets.** A Glance "brief" widget summarising the day's memories, and a
  SyncPad clips widget.

## Requirements

- Android 10 or newer (minSdk 29, targetSdk 37).
- JDK 11 or newer (Android Studio's bundled JBR is fine).
- An API key for an OpenAI-compatible provider, entered in the app's settings.
  Keys are stored in the app's private preferences on the device and are never
  part of this repository.

## Build and install

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`local.properties` (your SDK path) is generated by Android Studio and is not
tracked.

## Tests

The whole suite runs on the JVM - Robolectric supplies Android resources and the
Compose UI tests, so no phone or emulator is needed:

```bash
./gradlew :app:testDebugUnitTest
```

It covers three layers:

- **Unit tests** (`test/.../llm`, `memory`, `router`, `syncpad`, `tools`) -
  model catalog, fallback ladder, scoreboard, embedding, memory routing,
  clip parsing, call-choice parsing.
- **Integration tests** - the Room-backed memory repository and engine, the
  memory settings and LLM settings stores running against real (in-memory)
  implementations.
- **UI tests** - Compose screens driven through `createComposeRule` on
  Robolectric.

### Coverage

```bash
./gradlew coverageReport
```

JaCoCo reports are written to
`app/build/reports/jacoco/coverageReport/html/index.html` (HTML) and
`app/build/reports/jacoco/coverageReport/coverageReport.xml` (machine readable).
Generated Hilt, Room and `R`/`BuildConfig` classes are excluded. The report
covers the JVM suite only; activities, services, workers and Glance widgets
still need device tests (`androidTest`).

## Layout

```
app/src/main/java/com/example/heyandroid/
  assistant/   voice interaction, chat session, screen capture
  brief/       the full-screen brief page behind the widget
  data/        Room database, entities, DAOs and migrations
  llm/         providers, model catalog, scoreboard, fallback ladder
  memory/      memory engine, repository, local embeddings
  router/      keyword routing for voice/text input
  syncpad/     SyncPad client, repository, clip cache, settings
  tools/       tool schemas and implementations the assistant can call
  ui/          Compose screens and theme
  widget/      Glance and RemoteViews widgets, brief generation
  work/        WorkManager jobs for capture processing
```

Room schemas are exported to `app/schemas` and are the reference the hand-written
migrations are checked against.
